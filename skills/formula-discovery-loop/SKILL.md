# 公式发现闭环（Formula Discovery Loop）

目标不是「给出一个公式」，而是**用可被独立复核的证据证明这个公式是真的**。
核心不是搜索技巧，而是纪律：**先验证，再宣布**。

## 每轮必须按顺序执行

1. **声明假设**：一句话写出本轮要检验的函数形式，并说明依据（量纲、单调性、极限行为、上一轮的失败原因）。
2. **调用工具**：`python -m formula_agh verify --task <任务目录> --formula "<公式>" --params <自由参数> --run-id <编号> --out runs`
3. **读取结论**：输出 JSON 含 `verdict`、`checks`（每项 `passed`/`reason`/`metrics`）、`rounds_hint`。只有 `accepted` 才能进入第 5 步。
   一条命令会跑齐四道门，不需要你分别调用：`dimension`、`holdout`、`extrapolation`，
   以及若干条 `scale-*`（幂律标度 / 无量纲群 / 极限行为 / 单调性 / 符号 / 对称性）。
4. **显式处理失败**（评审最看重的部分）：
   - `dimension` 失败：该形式物理上不成立，**放弃这个函数族**，不要继续调参数。
   - `scale-*` 失败：**单位可能对、形状不对**——例如漏掉了某个自变量、或对某个量不是幂律关系。
     这类失败不看任何误差数字，所以它比阈值更硬：**必须换函数族**，调参数不会有改善。
   - `extrapolation` 失败：过拟合式发现（域内好、域外崩），**换函数族或加结构性约束**。
   - `holdout` 失败：域内都没拟合好，检查是否漏了变量或形式不对。
   - `fit` 失败：拟合不收敛，先怀疑函数形式，而不是反复换初值。
   - 每轮失败必须在下一轮假设里**引用上一条失败理由**，形成可追溯推理链。
5. **记录结论**：公式、拟合参数、四道门的指标、以及「我是否推翻过自己」。

## 六条硬约束

1. **禁止读取任何名为 reference / answer / ground_truth / solution 的文件**。那是评分用标准答案，读到即作弊，结论也失去意义。
   **同样禁止读取 `sealed/` 目录**：那里是留出集与外推集的数据点，读了就等于把考卷答案抄进来。
   你只应使用 `tasks/<id>/data.csv`（或 `data_train.csv`）与 `meta.json`。
2. **禁止跳过任何一项检验**。四道门都必须跑，不能因为「看起来对」就省略外推、量纲或尺度行为。
   注意：判定的误差口径是 `median(|预测-真值|/|真值|)`，阈值来自 `config/agent.yaml`；
   不要自己估算误差，也不要用别的口径自我安慰。
3. **禁止只报告成功轮次**。失败轮次必须进入结论，它们是「验证严谨性」与「异常处理」的直接证据。
4. **禁止在同一函数形式上反复微调参数来刷过阈值**。连续 3 次否决后必须更换函数族。
5. **禁止编造结论**。数据是纯噪声时，正确行为是报告「未发现稳定公式」。负对照下编出公式比没有结果更糟。
6. **禁止修改 data.csv、划分规则或阈值**。阈值统一在 `config/agent.yaml`；为让某个公式通过而放宽阈值属于作弊。

## 工具接口速查

```
验证单个公式：
  python -m formula_agh verify --task tasks/<id> --formula "G*m1*m2/r**2" --params G --run-id <run_id> --out runs

批量跑候选：
  python -m formula_agh batch --tasks tasks --out runs [--layer base]

校验任务集（含答案泄漏检测）：
  python -m formula_agh validate-tasks --tasks tasks
```

证据自动落盘于 `runs/<run_id>/`：`result.json`（结论）、`checks/*.json`（逐项检验，
尺度检验为 `scale-*.json`）、`command.txt`（复现命令）、`env.json`（环境快照）、
`run.json`（生效阈值、种子、自由参数名、**假设来源**）、`manifest.sha256`（防篡改校验）。

**你不需要自己归档**：`harness/run_verify.cmd` 在每次验证后会把这次运行自动复制进 `evidence/`
并更新索引。归档是纪律，由脚本保证。

**关于 `hypothesis_source`**：只有你（模型）自己提出假设的那些运行才应标为 `agh-llm`。
如果你的假设来自人给的清单或参考公式，如实标注——把人工编排的候选算成自主发现，
会被判为误导，比做不出结果更严重。

## 结论自评表

| 维度 | 合格线 |
|---|---|
| 任务完成度 | 至少一个任务给出 `accepted` 的公式，并与标准答案对照 |
| 验证严谨性 | 四道门（量纲/留出集/外推区/尺度行为）齐全，且有至少一条「自己推翻自己」的记录 |
| 异常处理 | 对 6 类异常各有一句处理说明 |
| 可复现性 | 任何人用 `command.txt` 的命令重跑，得到相同结论 |
