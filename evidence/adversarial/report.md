## 逐条说明

### 1. 数据缺失/异常值

- 攻击：在一个通过校验的任务里清空 8 行的 y 值，重新跑数据契约校验
- 期望：契约校验必须报 error 并拒绝该任务，不得静默通过
- 实测：error codes = CSV_NON_NUMERIC,TASK_ID_MISMATCH
- 说明：检测点在数据体检（契约校验），不是拟合阶段——缺失数据不该被带进拟合。

### 2. 拟合不收敛

- 攻击：给物理上不完整的候选式 R*n*T（漏掉体积项 1/V）做参数拟合
- 期望：判定 rejected，且失败项必须是 fit，理由指向函数形式而非初值
- 实测：verdict=rejected，失败项=fit，理由：参数拟合不收敛：残差过大（RMSE/std(y) = 0.811 > 0.500）
- 说明：给智能体的提示明确要求'先怀疑函数形式，而不是反复换初值'。

### 3. 量纲不一致（漏掉速度的平方）

- 攻击：把 m*v**2/2 改成 m*v/2（少一个速度因子）
- 期望：量纲检验必须 fail（J 对不上），整体 rejected
- 实测：dimension.passed=False，verdict=rejected
- 说明：该任务没有自由参数，因此走严格量纲比对，不存在'参数吸收单位'的模糊空间。

### 4. 物理荒谬但拟合好（人为给错单位）

- 攻击：把 meta.units 里速度的单位从 m/s 改成 m/s^2，公式本身不动
- 期望：量纲检验必须 fail：物理上说不通的表达式不能因为数值拟合好就通过
- 实测：dimension.passed=False，verdict=rejected
- 说明：这条同时验证了'量纲表缺单位'的风险已被堵住——修复前 8 个任务的量纲门是静默跳过的。

### 5. 外推崩溃 / 小角度近似

- 攻击：同时提交精确周期公式与小角度近似公式 2*pi*sqrt(L/g)
- 期望：精确式 accepted；近似式 rejected（域内已失真）
- 实测：精确式=accepted，小角度近似=rejected（失败项 holdout,scale-monotonic-theta0）
- 说明：这是项目最有说服力的一类对比：近似式在任何单点上都不荒谬，但整体不成立。

### 6. 过拟合（域内好、域外崩）

- 攻击：用 exp(-t/tau) 的三阶泰勒多项式做候选，模拟'只学到域内形状'
- 期望：理想情况下外推先于留出失败，判定 rejected
- 实测：verdict=rejected，holdout=False  rel=75.8329，extrapolation=False  rel=394.9042；失败项 holdout,extrapolation,scale-sign-y
- 说明：观察到的过拟合特征（留出通过、外推失败）= 否。无论是否命中该特征，只要整体被拒，就说明外推门在起作用。

### 7. 负对照（纯噪声输入）

- 攻击：把 4 个任务的 y 整体换成标准正态噪声，把正确答案原样送进去
- 期望：正确行为是全部 rejected（报告'未发现稳定公式'），编出公式比没有结果更糟
- 实测：phys-ohm -> rejected；phys-weight -> rejected；phys-gravitation -> rejected；phys-spring-energy -> rejected
- 说明：智能体侧对应纪律写在 AGH Skill 硬约束第 5 条。

### 8. 工具调用失败/恶意输入

- 攻击：送入恶意表达式、不存在的任务、语法错误公式、越界语法
- 期望：四类都必须被明确拦下：或抛专用异常，或判 rejected，绝不静默通过
- 实测：恶意表达式被 AST 白名单拦下=OK；任务目录不存在时抛 VerifyError=OK；语法错误公式被判 rejected=OK；条件表达式被拒=OK
- 说明：公式是不可信输入，因此求值层用 AST 白名单而不是 eval 直通。

### 9. 留出集隔离

- 攻击：在任务目录里放一个 reference.json；检查 split.json 与封印目录
- 期望：标准答案文件必须被校验拦下；划分文件不含行号；留出数据在 tasks/ 之外
- 实测：任务目录内出现 reference.json 时校验报 error=OK；split.json 不含行号索引=OK；留出集数据封印在 sealed/（tasks/ 之外）=OK
- 说明：这是从'口头保证没看过'升级成'文件系统上分开'的一步。

### 10. 外推区严格位于训练支撑域之外

- 攻击：对 22 个任务逐个数值核对：外推点是否都在训练支撑域之外、留出点是否都在之内
- 期望：100% 的外推点严格在支撑域外，100% 的留出点在支撑域内
- 实测：外推点 1320/1320 在域外；留出点 1760/1760 在域内；越界任务=无
- 说明：这是'外推'这个词能不能用的机器判据，不是描述性说法。

### 11. 量纲检验的覆盖面

- 攻击：统计 22 个任务里有多少个的量纲检验是真正执行的、有多少被静默跳过
- 期望：0 个任务被静默跳过；有单位信息的任务都必须真正执行量纲比对
- 实测：实际执行 22 个；跳过 0 个 
- 说明：修复记录：改造前单位表未收录 m^3 / T / F/m / H/m / ohm / m^2，8 个任务被静默跳过。补上复合单位解析后覆盖率到 100%。

### 12. 结论对随机种子的稳定性

- 攻击：把数据划分与拟合的种子换成 5 个不同值，重跑全部 22 条金标准公式
- 期望：结论不应随种子翻转；若翻转，必须明确指出是哪条任务、哪几个种子
- 实测：翻转 0 / 22 条
- 说明：种子只影响划分与多起点顺序，不影响判据本身；这条检验的是判据有没有过拟合到某一次划分。

### 13. 放水攻击：只放宽阈值不够

- 攻击：把两个误差阈值放宽到 3.0，先只放宽阈值，再叠加关闭尺度检验
- 期望：只放宽阈值不得放行错误公式（尺度门是独立的第二道防线）；必须同时关掉尺度检验才会被放行——说明放水需要改两处，且都会留在 config 的 diff 里
- 实测：默认：rejected；只放宽阈值：rejected（尺度门拦住）；放宽阈值+关尺度门：accepted
- 说明：结论：阈值仍是软肋，但已不是唯一软肋。评审 diff config/agent.yaml 即可看出有没有人同时动了阈值与开关。

### 14. 符号错误被自由参数吸收（已知边界）

- 攻击：把引力势能的负号去掉（+G*m1*m2/r），看判据能否识别
- 期望：如实报告：若符号被自由参数吸收而无法识别，必须写明这是边界，不得宣称能识别
- 实测：正确式=accepted，去负号=accepted（符号被吸收，判据无法区分）
- 说明：结论：符号可由自由参数吸收，因此本判据**不能**判定符号正确性；该风险交由 M3 的物理审查（现象描述、量纲与极限行为）兜底。
