## 二、命令速查

全部命令都可用 `python -m formula_agh <子命令>`，也可用 `harness\*.cmd` 包装脚本
（供 AGH 的命令工具直接调用）。

    # 看当前生效的判据与阈值（唯一来源 config/agent.yaml）
    python -m formula_agh settings

    # 任务集契约校验 + 答案泄漏检测（提交前用 --strict）
    python -m formula_agh validate-tasks --tasks tasks --reference reference --require-split --strict

    # 三段划分：生成并物理封印留出/外推集
    python -m formula_agh split --tasks tasks --sealed sealed
    # 重算并与已落盘结果比对（验收：完全一致）
    python -m formula_agh split --tasks tasks --check

    # 多重验证单个公式（量纲 / 留出集 / 外推区 / 尺度行为，一次跑齐）
    python -m formula_agh verify --task tasks/phys-gravitation --formula "G*m1*m2/r**2" --params G

    # 独立复算：对 runs/ 下每条运行重新划分、重新拟合、重新判定
    python -m formula_agh recheck --runs runs --tasks tasks --out recheck

    # 证据归档 + 双向孤儿检测（--prune 先打印清单再删未索引的证据目录）
    python -m formula_agh archive --runs runs --out evidence
    python -m formula_agh archive --runs runs --out evidence --check
    python -m formula_agh archive --runs runs --out evidence --prune

    # 评分（与标准答案对照，独立于智能体进程）
    python src/scoring/compare.py --runs runs --tasks tasks --reference reference --out evidence/scoring

    # 对抗性测试 / 负对照 / 判别力 / 尺度检验（后三个由 M3 维护）
    python examples/adversarial_suite.py
    python examples/negative_control.py
    python examples/discrimination_report.py
    python examples/scale_check_all.py [--variants]

    # 一键复现（15 步，最后与基线指纹逐字段比对）
    python reproduce.py --update-baseline     # 首次固化基线
    python reproduce.py                       # 之后每次比对，0 差异即复现成功
    python reproduce.py --clean D:\repro       # 复制到干净目录再跑

## 三、验证引擎在四道门之外还做了什么

1. **判定口径可复核**：每次运行同时记录多个误差口径（中位相对误差、p75、p90、RMS 相对误差、
   RMSE/中位|y|、RMSE/std(y)、最大相对误差）。评审可以换成旧口径重算，看结论会不会变。
2. **阈值单一来源**：所有入口从 `config/agent.yaml` 读同一组阈值与开关
   （`error_criterion` / `holdout_error_threshold` / `extrapolation_error_threshold` /
   `max_fit_residual` / `dimension_check` / `scale_check`）。改造前 `verify` 用 0.05、
   `batch` 用 0.08，同一公式两条命令两个结论；`demo_agent.py` 更是完全没传参数。
   现在有 `test_every_entry_point_passes_all_switches` 把接线钉死（连演示脚本一起管）。
3. **证据自校验**：`manifest.sha256` 覆盖运行目录内全部文件（含 `run.json`），
   `verify_manifest()` 可一键核对；`recheck` 每次都会顺带跑一遍。
4. **证据溯源必填**：`run.json` 的 `hypothesis_source` 区分模型自主提出、人工写死的演示装置、
   标准答案、人为构造的错误式等；**只有 `agh-llm` 计入评分脚本的"智能体发现"层**。
   归档索引按来源分组统计，并列出所有 `unclassified` 的运行。
5. **自动归档**：`harness/run_verify.cmd` 设置 `FORMULA_AGH_AUTOARCHIVE=1`，
   AGH 每调用一次验证工具就自动归档一条并更新索引——归档是纪律，由脚本保证，
   不依赖智能体记得去调用归档命令。
6. **复算范围诚实标注**：由其它判定套件（例如只跑尺度检验的 `scale-ref-*`）产出的运行，
   `recheck` 标为 `out-of-scope` 而不是硬凑成"一致"；
   判定相同但数值对不上的，标为 `stale-metrics` 并写明"应重跑后再引用"。

## 四、接口契约（给 M1 / M3）

### 4.1 M2 提供

| 接口 | 签名 | 说明 |
|---|---|---|
| 单公式验证 | `formula_agh verify --task <dir> --formula <expr> --params <names> --run-id <id>` | stdout 输出 JSON，AGH 直接读；自动归档（见第三节第 5 条） |
| 批量验证 | `formula_agh batch --tasks tasks --out runs [--layer base]` | 读每个任务下的 `candidates.json`；候选带 `expect` 字段时校验期望，不符即非零退出 |
| 契约校验 | `formula_agh validate-tasks --tasks tasks --reference reference --require-split` | 违规即非零退出 |
| 独立复算 | `formula_agh recheck --run-dir runs/<id>` | 单个运行复算，判定一致返回 0 |
| 划分 | `formula_agh split --tasks tasks --sealed sealed [--check]` | 生成 `split.json` 与 `sealed/`；`--check` 重算比对 |
| Python API | `from formula_agh.verify import verify_formula` | 返回 `VerifyReport`，含 `verdict`/`checks`/`free_parameters`/`rounds_hint` |
| 尺度检验接口 | `verify_formula(..., scale_check=True, scale_specs_path=...)` | **已采纳 M3 的方案 A**：尺度检验并入 `checks[]`，失败理由进下一轮提示 |

### 4.2 M2 需要 M1 / M3 保证

* **M3**：`tasks/<id>/data.csv` 列名与 `meta.json` 的 `var_names` 一致；
  `units` 用标准单位字符串；`free_parameters` 与自变量不同名；
  `physics/scale_specs.json` 覆盖全部任务（有 `test_scale_specs_cover_every_task` 守着）。
* **M1**：智能体只读 `tasks/<id>/data.csv` 或 `data_train.csv`，**不得**访问 `sealed/` 与 `reference/`；
  阈值改动一律改 `config/agent.yaml`，不得在提示词或脚本里硬编码；
  接入真实 AGH 后请确认产出的 `run.json.hypothesis_source` 为 `agh-llm`。
* **共同**：`runs/<run_id>/` 一经生成视为不可变证据；复核产物写到 `recheck/`。

## 六、已知边界（写进说明书，不藏）

1. **符号错误判据识别不了**。自由参数会吸收符号（去掉引力势能的负号后，
   拟合出的 G 取负值即可完全等价）。这类错误交 M3 的物理审查兜底，
   对抗性用例里如实标注为"无法识别"。
2. **量纲检验在缺单位信息时降级**。降级结果仍是 `passed=True`，
   但理由写明"跳过"，契约校验同时给 warn。**降级不会静默，但确实是降级。**
3. **封印只防目录遍历**。智能体若持有宿主机绝对路径仍可读到 `sealed/`，
   这依赖 AGH 的工作目录与沙箱策略，不在脚本能力范围内。
4. **外推区偏温和**。数据按声明区间均匀采样生成，两端不稀疏。
5. **归档是增量的**。`archive` 只复制真正变化的文件（比较大小与 mtime）。
   本机工作区单文件写入约 0.2 秒（实测复制 14 文件 / 30 KB 的目录要 2.8 秒），
   全量重拷 152 条运行要十几分钟，看上去像卡死。增量同步后，稳定状态下归档接近零拷贝。
6. **拟合粗筛用的是已弃用口径**。`max_fit_residual` 判据为 `RMSE/std(y) > 0.5`，
   即判定阶段弃用的那个口径。保留理由：它是"这个函数形式没戏"的粗筛而不是精度判定，
   松一点是刻意的；训练残差已按多种口径写入 `checks/fit.json` 供评审判断。
7. **智能体发现层只覆盖 1 个任务**。闭环已经打通——`runs/` 里有 2 条真实的 `agh-llm` 运行
   （`phys-gravitation`：第 1 轮 `G*m1*m2/r` 被尺度门以「r 的期望幂次为 −2」否决，
   第 2 轮 `G*m1*m2/r**2` 全门通过），评分表第三层因此不再是空的。
   但**覆盖度不足以声称通用发现能力**：22 个任务里只有 1 个走过自主闭环。
   接入过程与真实运行暴露的两个溯源缺陷（模型提出的假设被记成 `cli`、评分脚本按文件名判类）
   见 [M2_AGH接入阻塞报告.md](M2_AGH接入阻塞报告.md)。
   核验工具：`python examples/agnes_probe.py`（退出码 0/2/3/4 分别对应通过/配置/鉴权/推理）。
8. **有 13 条运行没有标注假设来源**（`unclassified`）。它们由流水线之外的脚本产出
   （`extrap-phys-*` 6 条、`m3-*` 3 条、`scale-demo-accept`、`demo-video-self-negation-01/02`），
   产生时 `hypothesis_source` 字段还不存在。`archive` 会把它们逐条列在 `evidence/ARCHIVE.md` 里，
   **不计入任何能力声明**。消除办法：产出方重跑一次（脚本已标注来源），或人工补注。
   这里不做"按前缀猜来源"的自动回填——推断出来的溯源等于没有溯源。
9. **工作区是共享的，存在并发写入**。`runs/` 下同时有三名成员的产出；
   `archive` 检测到源文件变化时会重拷贝并在 `source_changed` 中列出，不静默覆盖；
   `reproduce` 的指纹只覆盖本流水线自己的运行，队友运行的数量单独提示、不计入差异。
