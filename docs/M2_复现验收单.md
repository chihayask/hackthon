# 复现验收单（给陌生人用）

> 对应分工表 10-14：一键复现脚本 —— 在干净目录下执行成功，输出与历史记录一致；
> 以及协作机制的"彩排：全流程跑一次 + 提交材料逐项核对"。
>
> 这份文件的目标是：**一个没参与过本项目的人，照着做就能得出和我们一样的结论**。
> 如果哪一步你做不通，那是我们的问题，不是你的问题——请把卡住的那一步连同报错发给我们。

## 第 0 步：前提（2 分钟）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| Python | 3.10 以上（实测 3.13） | `python --version` |
| numpy | 已安装（唯一必需依赖） | `python -c "import numpy;print(numpy.__version__)"` |
| scipy / pytest | **不需要** | 缺了不影响；拟合用自带 LM，测试用自带 runner |

如果缺 numpy：`pip install -r requirements.txt`

## 第 1 步：一条命令复现全部结论（5–10 分钟）

在仓库根目录执行：

    python reproduce.py

**期望结尾**（数字可能因队友新增运行而更大，但"0 处差异"必须成立）：

    复现成功：指纹与基线完全一致。
      任务 22 个，本流水线运行 135 条，对抗用例 14 项，全部逐位一致。

若你的 python / numpy 版本与基线不同，会多出几行**环境提示**，形如：

    复现成功：结论逐位一致；另有 2 处环境差异（不影响判定）。
      - 环境：/environment/python: '3.12.14' != '3.13.5'
      基线环境：python 3.12.14 / numpy 2.3.5 / Windows；本次环境：python 3.13.5 / numpy 2.4.6 / Windows

**这仍然是复现成功（退出码 0）。** 指纹里的 python/numpy 版本与操作系统属于"复现环境"，
tasks / splits / runs / scoring 才是"结论"；只有结论判成败——否则换台机器"结果一字不差"
也会被判失败，那是把环境当结论。要连环境也逐字比，加 `--strict-env`。

结束前还会打印一行"智能体发现层：候选 N 条"。在干净目录里 N 必然是 0：
那几条真实 AGH 运行需要 AGH 实例 + 模型凭据 + 会话授权，**刻意不进指纹**，
只在工作区里单独汇报。这不是失败，也不影响上面任何结论。

若显示 **复现失败：与基线有 N 处差异**，脚本会逐行列出差在哪：
`/runs/variant-phys-ohm/verdict: rejected != accepted` 这样的行就是在告诉你
"哪个任务的哪个字段对不上"。把这段原样发给我们即可。

## 第 3 步：干净目录复现（10–15 分钟，这一步最关键）

第 1 步是在我们的工作区里跑的。真正要证明的是"从零也能跑出来"：

    python reproduce.py --clean D:\repro_verify

它先把源码复制到 `D:\repro_verify`（排除 `runs/ evidence/ recheck/ sealed/ superseded/`
与缓存目录），再在那个目录里从零执行全部 15 步。

**期望**：同样"复现成功：指纹与基线完全一致"。
注意被排除的 `sealed/` 与所有运行都是**在那个干净目录里重新生成的**——这正是一键复现要证明的事。

## 第 4 步：自己挑一个结论验一遍（5 分钟）

不想信汇总数字的话，挑一个具体结论手工验：

    :: 1) 看当前生效的判据与阈值
    python -m formula_agh settings

    :: 2) 拿一个正确答案送进去，应当 accepted
    python -m formula_agh verify --task tasks/phys-gravitation --formula "G*m1*m2/r**2" --params G

    :: 3) 拿一个物理上合理但结构错误的式子，应当 rejected
    python -m formula_agh verify --task tasks/phys-gravitation --formula "G*m1*m2/r" --params G

    :: 4) 打开第 2 条留下的证据，逐项看它凭什么接受
    type runs\<run_id>\result.json
    type runs\<run_id>\checks\holdout.json

第 4 步里 `checks/holdout.json` 的 `metrics` 同时给出**四种误差口径**。我们判定用的是
`relative_error_median`；你可以换成 `normalized_rmse` 自己重算一遍，看结论会不会变
——不会删掉对自己不利的口径，这也是可以核对的。

## 第 5 步：卡住了怎么办

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: formula_agh` | 没设 `PYTHONPATH` | 用 `python -m formula_agh ...` 前先 `set PYTHONPATH=src`，或直接用 `harness\*.cmd` |
| `UnicodeEncodeError` / 中文乱码 | 终端编码不是 UTF-8 | 加 `-X utf8`，并 `set PYTHONIOENCODING=utf-8` |
| `FileNotFoundError: ...\sealed\...` | 还没生成封印数据 | 先跑 `python -m formula_agh split --tasks tasks --sealed sealed`（`reproduce.py` 已包含这一步） |
| 复现报"新增/缺失"若干处 | 工作区里队友正在并发跑实验 | 用 `--clean` 在干净目录复现；那才是可比对的基准 |
| 复现报 `..._manifest_integrity...` | 某条运行的 SHA256 清单不完整 | 把那行贴给我们；清单覆盖 `run.json`，不完整即视为证据不可信 |
