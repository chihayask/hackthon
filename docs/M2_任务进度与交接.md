## 八、踩过的坑（照着看能省几小时）

1. **不设 `PYTHONPATH=src` 就直接 `python -m formula_agh`** → `No module named formula_agh`。README 的命令都假定已设好。
2. **把环境差异当复现失败**（已修）。指纹里混着 python/numpy 版本时，换台机器「结果一字不差」也会被判失败。现在只有结论判成败，环境差异只提示；`--strict-env` 可还原严格模式。回归测试：`test_environment_differences_do_not_fail_reproduction`。
3. **包装脚本的默认来源标注**。`harness/run_verify.cmd` 默认把 `hypothesis_source` 标成 `agh-llm`——它假设调用者一定是 AGH。**人工调试前先** `set FORMULA_AGH_HYPOTHESIS_SOURCE=cli`，否则会产生**假溯源**（本项目真的发生过一次，已删除记录并重跑）。
4. **别按文件名判类**。评分脚本曾经按 run_id 前缀判类，导致真实 AGH 运行（叫 `20261008-231054-phys-gravitation`）被归进 other，**一条货真价实的自主发现被排除在对照表外**。现在按 `hypothesis_source` 判类。
5. **`runs/` 一经生成即不可变**。复核产物写 `recheck/`，绝不改写 `runs/`。
6. **归档是增量的**。全量重拷 152 条要十几分钟，看上去像卡死；稳定状态下接近零拷贝。
7. **`.env` 不进干净目录**。`reproduce.py --clean` 已黑名单隔离，并有一条防回归断言（干净目录里出现密钥文件直接报错）。
8. **工作区是共享的**，队友会并发写 `runs/`。`archive` 检测到源文件变化会重拷贝并列入 `source_changed`，不静默覆盖；`reproduce` 的指纹只覆盖本流水线自己的运行。
9. **别删 `superseded/runs/`**。那是任务已不存在的历史运行，已隔离、未删除，删掉等于毁证据。
10. **AGH 的 key 与 AGH 的路由是两件事**。直连推理端点 401 不代表 AGH 不可用——AGH 自己存的账户路由是通的。
11. **本机 `pwsh` 是 Windows PowerShell 5.1**（不是 PowerShell 7）：`Tee-Object` / `Out-File` 默认写
    **UTF-16LE**，拿它当 UTF-8 读会 `UnicodeDecodeError: 0xff`。要字节精确的运行日志用
    `cmd /c ... > log 2>&1`，或让 Python 自己写文件。

## 九、已知缺陷与边界（照实写，不藏）

1. **符号错误判据识别不了**：自由参数会吸收符号（去掉引力势能公式的负号后，G 取负值即可完全等价）。交 M3 的物理审查兜底，对抗性用例里如实标注为「无法识别」。
2. **量纲检验在缺单位信息时降级为「跳过」**：降级结果仍是 `passed=True`，但理由写明跳过，契约校验同时给 warn。**降级不会静默，但确实是降级。**
3. **封印只防目录遍历**：智能体若持有宿主机绝对路径仍可读到 `sealed/`，取决于 AGH 的工作目录与沙箱策略。
4. **外推区偏温和**：数据按声明区间均匀采样生成，两端不稀疏。
5. **拟合粗筛用的是已弃用口径**（`RMSE/std(y) > 0.5`）：它是「这个函数形式没戏」的粗筛而非精度判定，松一点是刻意的。
6. **13 条运行没有标注来源**：由流水线之外的早期脚本产出，产生时字段还不存在。已逐条列出，不计入任何能力声明。
7. **智能体发现层只有 1 个任务**：闭环通了，但覆盖度还不足以声称通用发现能力。
