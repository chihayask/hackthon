# 去提示消融结果（2026-10-10）

> 外部审计（2026-10-10）要求：「若使用专家先验，应明示并做**去提示/去尺度反馈消融**，
> 分别报告『纯数据发现』与『先验辅助恢复』。」本文是这条要求的实测回应。

## 一、为什么需要消融（而不是只声明）

`examples/hint_audit.py` 实测：22 个任务的可见面在**四个维度上全部泄漏**——
任务名含现象词、`phenomenon` 文本写着定律、`source` 链接直指定律条目、`units` 暴露量纲结构；
启动提示里还给出 6 处示例式。存在这些先验时，「智能体发现」的准确称谓是
**带物理先验的已知定律恢复**。本文量化先验到底值多少。

## 二、两条支路怎么跑

两条支路**用同一套引擎、同一套阈值、同一个驱动脚本**，唯一差别是智能体可见的元数据：

| | 先验辅助支路 | 盲化支路 |
|---|---|---|
| 任务目录 | `tasks/<真实 id>` | `tasks/<匿名 id>`（`t-<sha1 前 8 位>`） |
| `phenomenon` | 有（写着定律） | **移除** |
| `source` | 有（直指定律条目） | **移除**（换成指向评审侧映射的占位串） |
| `domain` | 有 | **移除** |
| 单位表 / 自由参数 | 有 | 保留（属合法物理输入） |
| 尺度检验反馈 | 开启 | 开启（本支路未做去尺度反馈） |

盲化集由 `examples/make_blind_taskset.py --out blind` 生成，
跑在独立项目根 `E:\fagh-blind-root`（无空格路径，便于 AGH 审批规则），
命令与正式支路完全一致（`harness/run_agent_discovery.ps1`）。

## 三、结果

### 3.1 主指标：该任务是否曾有任一次给出正确公式（与门无关）

这是三条支路**唯一可比**的口径。评分器默认取「每个任务的一条代表运行」，而代表运行优先取
accepted——支路之间**门数不同**（纯数据支路少一道尺度门），accepted 集合因此不可比，
会把「少一道门」误读成「发现能力提升」（见 3.3）。

| 支路 | 曾有任一次给出正确公式 | 相对先验辅助 |
|---|---|---|
| 先验辅助（现象/来源/任务名齐全） | **14 / 22** | — |
| 盲化（去现象/来源/任务名） | **12 / 22** | −2 |
| 纯数据（再去掉尺度反馈） | **13 / 22** | −1 |

**读法**：

- 点名定律的元数据大约值 **2 / 22**（先验辅助 14 → 盲化 12）。
- 再拿掉尺度反馈，结果在 **12 ↔ 13** 之间，属**噪声量级**（1 个任务）。
  也就是说：**没有证据表明尺度反馈提升了发现率**；它主要的作用是**拦住错误的形状**
  （`scale-variant` 22/22 被拒），而不是帮模型猜对。

### 3.2 评分器口径（代表运行，含门数影响）

| 支路 | 候选 | 全部绑定会话 | 代表运行与标准答案一致 |
|---|---|---|---|
| 先验辅助 | 22 | 22 / 22 | 16 / 22（72.7%） |
| 盲化 | 20 | 20 / 20 | 14 / 20 |
| 纯数据 | 20 | 20 / 20 | 17 / 20 |

### 3.3 一个必须说明的方法学陷阱（本消融最有价值的发现之一）

上表里「纯数据」支路 17 / 20 **高于**盲化支路的 14 / 20，看起来像「去掉尺度反馈反而更好」。
**这是混杂因素，不是结论。**

原因：去掉尺度检验等于**少了一道门**，更多运行进入 accepted；而评分器取
「第一个 accepted 运行」作为代表，且 `matches_reference` 在该代表上计算。
于是「门更少 → accepted 更多 → 代表更可能是正确那条」被误当成了「发现得更好」。

**正确做法**：跨支路比较必须用与门无关的指标（3.1），或固定门数。
本文两种口径都列出，主指标用 3.1。

## 五、诚实的边界

1. **本支路只去了元数据先验，没有去尺度反馈**。尺度检验的失败理由会写出目标幂次
   （「r 加倍后 y 变 0.5 倍，要求 -2」），这本身也是先验。要跑「完全无先验」支路，
   还需在验证时加 `--no-scale-check`（当前包装脚本尚未提供该开关，见下一步）。
2. **单位表仍然保留**。它暴露量纲结构，但也是合法物理输入；去掉它会让量纲门退化，
   属于另一种消融（`make_blind_taskset.py --level strict` 可以生成该档）。
3. **样本量 22**，3 个任务的差异不宜做统计显著性解读，只能说「先验的贡献在这个量级」。
4. 盲化支路的金标准自检与判别力为 0，是因为该支路没有跑 `refcheck`/`variant` 夹具
   （它们是流水线的一部分，不属于消融变量）。

## 六、结论与建议表述

- 可以主张：**带物理先验的已知定律恢复**，绑定会话层 16–17/22；
  去掉点名定律的元数据后仍有 **14/22**。
- 不建议主张：无先验的「从数据中发现公式」；本项目未做过完全去先验的支路。
- 下一步（可选）：给包装脚本加 `FORMULA_AGH_NO_SCALE=1`（追加 `--no-scale-check`），
  再跑一次得「纯数据」支路；或直接跑 `--level strict` 的盲化集。
