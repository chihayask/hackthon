# 尺度一致性检验说明

> 本文档说明 **为什么需要这一层判据**、**它检查什么**、**怎么用**、**它的边界在哪**。
> 目标读者是接入 AGH 的开发者，以及需要独立复现的评审。

---

## 一、为什么量纲不够

三重验证里的量纲检验排得掉"单位不对"的公式，排不掉"**单位对、形状错**"的公式。

最典型的例子：把万有引力的平方反比写成一次反比。

    G*m1*m2/r**2    <- 正确
    G*m1*m2/r       <- 错误

两者在量纲上都"说得通"，因为 G 是自由参数，**参数可以把单位差吸收掉**。
拟合时 G 会自动取一个"看起来合理"的值，把误差压下去一部分。

尺度检验问的是另一个问题，它不看残差：

* 距离加倍，引力是不是变成**四分之一**？
* 振幅变大，单摆周期是不是**变长**？
* 时间足够长，剩余粒子数会不会变成**负数**？

这三个问题都不需要拟合、也**不依赖拟合残差阈值**；尺度判定只看公式本身的结构。需要说明的是：标度比较仍带有量级上的数值容差（见 `src/formula_agh/scale_checks.py` 的默认容差），因此准确的表述是「不依赖拟合误差阈值」，而不是「完全没有阈值」。

## 二、六类判据（任务书要求 >=3 类，实际实现 6 类）

| 判据 | 检查什么 | 物理出处 | 条数 |
|---|---|---|---|
| **scaling** 幂律标度 | 变量按 lambda 缩放后 y 应变为 lambda^p | 相似性原理、量纲分析的幂律形式 | 46 |
| **invariance** 无量纲群不变性 | 按指定指数同时缩放后 y 不变 | Buckingham pi 定理 | 1 |
| **limit** 极限行为 | 变量趋于某值时 y 趋于给定极限式 | 小量近似（线性化）、边界退化 | 3 |
| **monotonic** 单调性 | y 对某变量在声明区间内单调 | 力学、热力学中的单调响应 | 31 |
| **sign** 符号 | y 在采样盒内恒正 / 恒负 | 能量、力、粒子数的物理符号约定 | 22 |
| **symmetry** 交换对称性 | 同类变量互换后 y 不变 | 同类量的地位对称 | 3 |
| | | **合计** | **106** |

几条值得单独说的设计：

* **标度检验也能检验物理常数**。`f = (A-B)/h` 对 `h` 是 -1 次幂——"常数以什么幂次进入公式"是可检验的。
* **单调性检验会自动切换采样方式**。变量跨度 >= 10 倍时改用等比采样。原因是物理上"把质量加倍"是有意义的扰动，"把质量加 1e-27 kg"不是；线性采样会让 `q*B/m` 在高质量端看起来像常数，把正确公式误判成"漏掉质量"。
* **符号检验用变量的笛卡尔积网格**，不是逐变量扫描。"剩余粒子数为负"这类错误只在若干变量同时取极端值时才暴露。
* **极限检验逐探测点归一化**。若用最粗探测点统一作分母，一个恒定的**相对**偏差会随探测点变小而显得像在收敛，从而放过错误公式。

## 三、规格文件：`physics/scale_specs.json`

规格描述的是"**这个现象必须满足什么**"，与任何具体公式无关。因此同一份规格既能验证参考公式，也能验证智能体给出的候选式，且**不泄露答案**。

    {
      "schema": "formula-agh/scale-specs@1",
      "tasks": {
        "phys-pendulum-exact": {
          "physics_note": "有限振幅单摆周期 …… theta0 -> 0 时必须退化为小角度公式",
          "nominal_parameters": {},
          "checks": [
            {"kind": "scaling", "var": "L", "lambda": 4.0, "expect_power": 0.5,
             "note": "摆长变 4 倍，周期变 2 倍"},
            {"kind": "limit", "var": "theta0", "to": 0.0, "target": "2*pi*sqrt(L/g)",
             "note": "theta0 -> 0 时退化为小角度周期公式"},
            {"kind": "monotonic", "var": "theta0", "direction": "increasing",
             "note": "振幅越大周期越长；小角度公式在此处完全平坦，必被否决"}
          ]
        }
      }
    }

规格由机械成员按物理先验逐条编写，生成脚本为 `examples/make_scale_specs.py`。

**红线**：`physics/` 与 `reference/` 同等对待——位于 `tasks/` 之外，**绝不进入智能体上下文**。
智能体只能看到 `tasks/<id>/data.csv` 与 `meta.json`。

## 四、怎么用

### 4.1 命令行（供 AGH 的命令工具调用）

    python -m formula_agh.scale_checks --task tasks/phys-gravitation --formula "G*m1*m2/r" --params G=6.674e-11 --run-id scale-check-01 --out runs

退出码：`0` 全部判据通过；`1` 存在未通过项；`2` 用法或输入错误。

stdout 是 JSON（含 `verdict`、逐项 `checks` 的 `passed/reason/metrics`、以及 `rounds_hint`），
可直接被智能体消费；同时会在 `runs/<run_id>/` 落盘全套证据。

`--params` 支持 `G=6.674e-11` 与 `G`（只给名字时回退到规格里的物理真值）两种写法。
**尺度检验不需要拟合**：它只需要参数的量级与符号。

### 4.2 批量自检

    python examples/scale_check_all.py
    python examples/scale_check_all.py --variants

第一条跑 22 个参考公式，期望 22/22 通过；第二条跑 22 个结构错误式，期望 0/22 通过。

### 4.3 单元测试

    python run_tests.py tests/test_scale_checks.py

12 项测试，覆盖两个方向：不能误杀（参考式全过）、不能放水（错误式全拒），
以及"尺度检验运行期一次都没打开过标准答案"的行为验证。

## 五、判定语义

采纳语义是 **AND 门**：所有判据都通过才 `accepted`。

| 情况 | 判定 | 给智能体的提示 |
|---|---|---|
| 全部判据通过 | `accepted` | 量纲之外，公式的物理形状也已核对 |
| 任一判据不通过 | `rejected` | 未通过项逐条列出；说明"单位可能对、形状不对"，**必须换函数族，继续调参数不会改善** |

失败理由写得具体到可以直接指导下一轮假设，例如：

    在 theta0 ∈ [0.05, 1.2] 上用等比网格扫描 9 点：整体相对变化 0.000e+00；
    有 8 个步长方向相反（极值 0.000e+00），不满足全程递增

智能体读到的信息是"这个公式对 theta0 完全没有依赖"，而不是"效果不好"。

## 六、验收结果

| 验收项 | 结果 | 证据 |
|---|---|---|
| 参考公式通过 | **22 / 22** | `runs/scale-ref-*/result.json` |
| 结构错误式被拒 | **22 / 22** | `runs/scale-variant-*/result.json` |
| 单判据判别力 | 22/22（六类判据中最高） | `evidence/discrimination.json` |
| 阈值敏感性 | 四组阈值下联合判定均为 22/22、零误杀；其中三组里漏网的一例恰由尺度检验拦下 | `evidence/threshold_sensitivity.json` |
| 尺度检验回归测试 | 12 项 | `tests/test_scale_checks.py` |

**关于"增量价值"的诚实说明**：在当前生效的严格阈值下，三重验证单独就能拦下全部 22 个结构错误式，
尺度检验的**增量是 0**。它的价值不在于这批用例，而在于**判别力不依赖阈值的具体取值**——
换一组阈值，三重验证会放过一例，而尺度检验仍然拦得住。详见 `evidence/判别力与阈值敏感性.md`。

## 七、与量纲检验的互补关系（重要，且对答辩口径有直接影响）

对量纲检验做过一次独立验收（`examples/dimension_acceptance.py`），结论必须如实说：

| 项 | 任务数 | 说明 |
|---|---|---|
| 量纲门**严格生效** | 13 / 22 | 无自由参数或单位全部可识别 |
| 量纲门**降级** | 9 / 22 | 存在自由参数，引擎如实标注"严格比对推迟"，**不假装通过** |
| 降级且被尺度门覆盖 | **9 / 9** | 无一任务处于无人看守状态 |
| 降级且无人覆盖 | 0 | — |

**因此答辩时的正确表述是**：
"22 个任务里 13 个走严格量纲比对，另外 9 个因为存在自由参数而降级为结构一致性检查；
这 9 个全部由 106 条尺度判据补位。物理侧 22 个任务全部有门。"

**不能说的表述**："每个任务都做了严格的量纲检验。"（详见 `evidence/交叉评审发现.md`）

## 八、已知边界（写进说明书，不藏）

1. **规格是手工编写的**，覆盖 22 个任务。扩展到新任务需要机械成员先写规格——
   这是本方法的真实成本，不是"全自动"。
2. **符号与单调性判据依赖参数取值的符号**。若候选式的自由参数被拟合为负值，
   符号预期可能整体反过来。当前做法是用物理真值的符号做检验；这一点在
   `nominal_parameters` 里显式声明，没有隐藏。
3. **极限检验的探测点允许略微越出采样盒**。极限是函数形式的性质，不是数据的性质；
   但如果公式在采样盒之外本来就没有定义（如 log 的定义域），该判据会以
   "不可求值"报错而不是误判通过。
4. **`invariance` 只实现了 1 条**（掩星光深的半径比）。它是一个示例，
   证明 Buckingham pi 这类检验可实现；真正推广需要更多无量纲群分析任务。
5. **尺度检验不能替代拟合**。它只看函数形式与参数符号，不判断参数数值是否落在物理量级上。
   "参数恢复了真值"这件事由拟合与评分脚本负责，不属于本工具的职责。
