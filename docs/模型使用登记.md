## AGH 轨迹导出的真实性（2026-10-14 主办方通知后补充）

主办方在群里提醒：多数队伍「让 AI 自己去导出轨迹」，导出内容大多有误，
**必须通过 AGH 手动导出**。本项目对此做了逐条核验，结论如下。

**本项目的轨迹分两部分**：

* **提交材料引用的 25 个会话**：2026-10-14 **在 AGH 图形界面中逐个手动导出**，
  每份为官方诊断包 `agh-diagnostics-<短ID>-<时间戳>.zip`（含 `events.jsonl` 事件账本、
  `index.html` 可读报告、`trace.json`、日志）；
* **其余 44 个会话**：由 `agh export <sessionId>` 导出，同样读取守护进程的**完整事件账本**
  （`readLedger` → 全量事件游标），机械转储、不经过模型。

两者都是 AGH 的原始账本，不存在「让 AI 写一份轨迹」的环节。

**核验方法与结果**：逐条比对导出文件与会话库 `~/.agh/data/sessions.db` 的 `events` 表
（`session_key` + `seq` + `id` + `type`）。

    python examples/verify_agh_export.py

结果：**69 份导出全部与事件库完全一致（69 / 69）**，见 
`evidence/agh_export_verification.txt`。

**仍需队伍确认的一点**：若赛事方要求的是「在 AGH 图形界面里点导出按钮」这一具体动作，
请在 Agnes 控制台中按截图所示手动导出一次，替换 `evidence/agh-sessions/` 下的文件。
本项目的导出在**内容**上与之一致（同一份事件账本），但操作路径不同。

## 二、调用方式

模型不由本项目的 Python 代码直接调用，而是**经 Agnes Harness（AGH）CLI 调用**：

    node <agh>/packages/cli/dist/local/agnes.mjs -p "<提示词>" --mode json --cwd <工作区>

批量驱动脚本：

| 脚本 | 作用 |
|---|---|
| `harness/run_agent_discovery.ps1` | 逐任务建工作区、装技能、预建 AGH 会话、调用模型、导出轨迹 |
| `harness/run_verify.cmd` | 给模型当作工具调用的验证入口（由 AGH shell 工具执行） |
| `examples/model_guard.py` | 运行前的路由守卫：任一路由非 Agnes 即拒绝运行（退出码 2） |

调用参数：每次一个任务、最多 3 轮、会话模式 `--mode json`。

## 三、使用环节（以及**没有**使用模型的环节）

| 环节 | 是否调用模型 | 说明 |
|---|---|---|
| 假设生成（提出候选公式） | **是** | 模型自主提出候选形式，是「智能体发现」层的唯一来源 |
| 依据验证反馈重构假设 | **是** | 每轮失败理由回灌模型，由它决定下一步换什么函数族 |
| 参数反演（仿真任务线） | **是** | 智能体通过 `sim/probe.py` 逐步取回参数与残差后判读，见 `docs/仿真任务线.md` |
| 数值拟合 | 否 | 确定性最小二乘，见 `src/formula_agh/` |
| 量纲 / 留出 / 外推 / 尺度判据 | 否 | 确定性检查，阈值只在 `config/agent.yaml` |
| 评分与对照 | 否 | `src/scoring/compare.py`，`reference/` 仅它可读 |
| 一键复现与指纹比对 | 否 | `reproduce.py` |

**这样区分是必要的**：判定结论一律来自确定性代码，模型只负责「提出什么」。
否则模型既当运动员又当裁判，结果不可信。

## 四、AGH 执行记录（可人工核查）

| 记录 | 数量 | 位置 |
|---|---|---|
| AGH 原生会话页（HTML） | 68 份 | `evidence/agh-sessions/*.html` |
| AGH 原生轨迹（agnes.jsonl） | 68 份 | `evidence/agh-sessions/*.agnes.jsonl` |
| 其中**绑定会话**的成对记录（`bound_*`） | 24 组 | 由 22 任务绑定重跑产生 |
| **仿真任务线**的会话记录 | 1 组 | `evidence/agh-sessions/sim-inversion-20261012-114450.html` 与 `evidence/agh-sessions/sim-inversion-20261012-114450.agnes.jsonl`（136 个事件） |
| 运行记录（含 `session_id` 与 `provenance_bound`） | 332 条运行 / 31 条绑定 | `runs/*/run.json` |

**怎么人工核查**：

1. 打开任一份 `evidence/agh-sessions/bound_<任务>-<时间戳>.html`，可看到该次会话的完整工具调用序列；
2. 在同名 `.agnes.jsonl` 里可逐条核对输入输出；
3. 用其中的 `session_id` 到对应 `runs/<run_id>/run.json` 对上，
   该文件同时记录 `hypothesis_source`（须为 `agh-llm`）与 `provenance_bound`（须为 true）；
4. `src/scoring/compare.py` 的绑定层统计只计入**已绑定**的运行，
   标签自报而无会话号的运行**不计入**——这是 2026-10-10 外部审计提出后加的约束。
