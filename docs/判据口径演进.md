# 验证口径修正记录

> 这份文件记录一次**自我否定**：我们原来的"对不对"判据本身是错的，
> 它误杀了正确答案，同时放过了近似式。修正过程、原始数据、可复核命令全部写在下面。

## 一、问题从哪来

验证引擎的职责是"让对不对由机器判定"。所以第一步不是相信判据，而是攻击判据。

攻击方式是：把 22 条**标准答案**原样送进我们自己的验证引擎。
如果它们有的过不了，那多半不是标准答案错了，是我们错了。

结果当场抓到一条：

    phys-energy-shift   y = (A - B) / h        （普朗克关系式，标准答案）
    逐点最大相对误差 3.4%，但旧判据算出 0.0641 > 阈值 0.05 -> 判定 rejected

一条正确的物理定律被我们自己的判据拒绝了。这是必须修的缺陷。

## 二、第一版判据为什么错

旧判据：`normalized_rmse = RMSE / std(y)`

它把两件不相干的事混在一起：

* 预测准不准（我们要量的）
* 目标量 y 本身在不同样本间变化幅度大不大（跟预测质量无关）

`phys-energy-shift` 的 y 大体上就是一个量级（std/中位 = 0.19），
于是"分母小 -> 比值大"，相对精度 3.4% 的公式被判失败。
而 `phys-cyclotron` 的 y = qB/m 跨 17 倍动态范围（std/中位 = 17.6），
同样的相对精度反而轻松通过。

一句话：**这个口径量的是动态范围，不是精度。**

## 三、三次口径演进与实测数据

我们对四种候选口径做了同一套实验：
22 条金标准 × 5 个随机种子，21 条"物理上合理但结构错误"的候选式。

    口径                                 金标准最坏值   错误式最好值   分离倍数
    RMSE / std(y)                            0.0697        0.2255        3.23
    RMSE / 中位|y|                           0.0876        0.1855        2.12
    RMS 逐点相对误差                           3.7610        0.1817        0.05
    median( |pred-truth| / |truth| )         0.0130        0.1374       10.58   <-- 采用

最终采用的判据：

    relative_error_median = median( |pred - truth| / |truth| )

逐点相对误差的中位数：无量纲、对目标量动态范围免疫、对近零尾部稳健。

### 为什么不是另外三个

* `RMSE / std(y)`：上文所述，误杀 `phys-energy-shift`。
* `RMSE / 中位|y|`：修好了误杀，但它仍是**全局**口径。
  `phys-cyclotron` 的 RMSE 被少数大 |y| 点主导，换一个划分种子就在
  0.015 ~ 0.088 之间跳（实测），判定随种子翻转。这是"结论不可复现"，
  比误杀更严重。同时它把 `2*pi*sqrt(L/g)`（小角度近似）当成正确公式放行了
  （0.047 < 阈值 0.05）。
* `RMS 逐点相对误差`：对 `phys-radioactive-decay` 不可用。
  该任务 y = N0·exp(-t/tau)，t/tau 最大到 10，输入端的噪声被放大成
  输出端几十倍的相对误差，RMS 被这条尾巴整个带偏（金标准最坏值 3.76）。

## 四、修正后的验收数据

用当前判据（阈值：留出集 0.02、外推区 0.03，写在 `config/agent.yaml`）：

| 检验 | 结果 |
|---|---|
| 金标准自检（22 条标准答案） | **22 / 22 accepted** |
| 判别力（22 条结构错误的候选式） | **22 / 22 rejected** |
| 小角度近似 `2*pi*sqrt(L/g)` | **rejected**（中位相对误差 0.0276 > 0.02） |
| 三阶泰勒冒充指数衰减 | **rejected**（中位相对误差 4.40） |
| 换 5 个随机种子重跑 22 条金标准 | **翻转 0 条** |
| 最大间隔 | 金标准最坏 0.0130，错误式最好 0.1374，相差 10.6 倍 |

阈值 0.02 落在 [0.0130, 0.0276] 这个空隙里：
上离错误式最松的一条（小角度近似）还有 1.4 倍余量，下离金标准最差的一条有 1.5 倍余量。

## 五、判决权交回评审

四个口径的数值**全部**写进每一次运行的证据里：

    runs/<run_id>/checks/holdout.json
      metrics.relative_error_median   <-- 判定用
      metrics.relative_error_p75
      metrics.relative_error_p90
      metrics.rmsre
      metrics.relative_rmse
      metrics.normalized_rmse
      metrics.max_relative_error
      metrics.nonfinite_ratio

也就是说，评审可以换成旧口径自己复核一遍，看我们的结论会不会变。
我们没有把不利于自己的口径删掉。

## 七、这次修正暴露出的同类问题（一并已修）

修正口径时顺带查出的、同样是"判据自己有问题"的缺陷：

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | 单位表未收录 `m^3`/`T`/`F/m`/`H/m`/`ohm`/`m^2` | **8 个任务的量纲检验被静默跳过**，量纲门形同虚设 | 增加复合单位解析，覆盖率 22/22 |
| 2 | `parse_formula` 未捕获 `SyntaxError` | 一个语法错误的公式能让整条流水线崩掉（未捕获异常） | 与 `compile_formula` 对齐，转成 `UnsafeExpression` 并按不通过处理 |
| 3 | `run.json` 不在 `manifest.sha256` 里 | "防篡改清单"覆盖不到承载结论的文件 | 调整落盘顺序，清单写入前先写 run.json |
| 4 | 拟合失败时证据不记录自由参数名 | 独立复算会走成另一条分支（严格量纲比对 vs 结构一致性），3 条运行无法复算 | `VerifyReport.free_parameters` 与拟合值分开记录 |
| 5 | `verify` 与 `batch` 默认阈值不同（0.05 vs 0.08） | 同一公式走两条命令得到不同判定 | 阈值统一到 `config/agent.yaml`，由 `settings.py` 单一来源读取 |

第 1 条和第 5 条是"判据放水"的典型：一个让整类检验静默跳过，
一个让同一份公式在不同入口得到不同结论。两条都已经修掉并写进了对抗性用例。
