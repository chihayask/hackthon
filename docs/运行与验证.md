# 运行与验证说明（M1 交付）

本目录包含 FORMULA-AGH 的可运行核心：**三重验证引擎 + 证据归档 + AGH 接入脚手架**。

## 一、已实现并自测通过的部分

| 模块 | 文件 | 作用 |
|---|---|---|
| 安全求值 | `src/formula_agh/safe_eval.py` | AST 白名单：公式是不可信输入，越界语法直接拒绝 |
| 量纲分析 | `src/formula_agh/units.py` | SI 七基本量纲推断，为机械队友的物理审查提供工具 |
| 三重验证 | `src/formula_agh/verify.py` | 留出集 / 外推区 / 量纲三项检验 + 判定与自我否定提示 |
| 证据归档 | `src/formula_agh/evidence.py` | 生成 `runs/<run_id>/` 全部证据与 SHA256 清单 |
| 命令行 | `src/formula_agh/cli.py` | `verify` / `batch` / `validate-tasks`，输出 JSON 供智能体消费 |
| AGH Skill | `skills/formula-discovery-loop/SKILL.md` | 把「假设→拟合→三重验证→自我否定」固化成智能体纪律 |
| AGH 脚手架 | `harness/*.cmd` | 供 AGH 命令工具直接调用的包装脚本 |
| 自测 | `tests/test_verify.py` + `run_tests.py` | 10 项测试全部通过 |

**自测结果**：`10 passed / 0 failed`；任务集校验 4 个任务全部通过，无答案泄漏。

## 二、依赖说明（重要）

* 本机环境**没有 scipy、也没有 pytest**，且无法安装。
* 因此参数拟合改为**纯 numpy 的 Levenberg–Marquardt**（检测到 scipy 时自动优先使用），测试用自写的零依赖 runner。
* 运行时只需 `numpy`。这是刻意设计：**依赖越少，越不容易在比赛机器上崩**。

## 三、常用命令

```bash
# 任务集校验（含答案泄漏检测）
python -m formula_agh validate-tasks --tasks tasks

# 验证单个公式
python -m formula_agh verify --task tasks/mech-gravity --formula "G*m1*m2/r**2" --params G --run-id demo-01 --out runs

# 批量验证（读取每个任务下的 candidates.json）
python -m formula_agh batch --tasks tasks --out runs [--layer base]

# 自测
python run_tests.py
```

Windows 下也可直接用 `harness\run_verify.cmd`、`harness\run_batch.cmd`、`harness\run_validate_tasks.cmd`。

## 四、三重验证在检什么

| 检验 | 定义 | 为什么需要 |
|---|---|---|
| 留出集 | 中间区域内随机留出、智能体不可见的点 | 排除记忆式拟合 |
| **外推区** | **主自变量最小端 + 最大端**（严格位于训练支撑域之外） | **区分「拟合」与「真发现」** |
| 量纲 | 无自由参数时严格比对；有自由参数时做结构一致性检查 | 排除数学上成立、物理上荒谬的表达式 |

量纲检验分两级是刻意取舍：参数（如 G、k）本身可以吸收单位，若强行要求公式量纲等于 y 的量纲，会把**正确的物理公式误杀**。

## 五、判定与自我否定

| 情况 | 判定 | 给智能体的提示 |
|---|---|---|
| 三项全过 | `accepted` | 可归档结论 |
| 仅量纲失败 | `rejected` | 物理荒谬，**换函数族**，禁止调参数 |
| 仅外推失败 | `rejected` | 过拟合式发现，**换函数族或加结构性约束** |
| 其他失败 | `rejected` | 针对失败项提出新假设 |
| 拟合不收敛 | `rejected` | 先怀疑函数形式，而非换初值 |

## 六、证据规范（对应赛事硬性要求）

```
runs/<run_id>/
  command.txt        可复制的复现命令
  env.json           Python/平台/时间戳快照
  result.json        公式、参数、三项检验、最终判定
  checks/*.json      每项检验的独立记录（含指标与理由）
  run.json           任务、输入、备注
  manifest.sha256    全部文件的 SHA256 清单（防篡改）
  figures/           图表目录（留给 M3 放外推崩溃图）
```

**失败结果同样归档**——失败案例是「验证严谨性」与「异常处理」的直接证据。

## 七、接入 AGH 的步骤（M1 待办）

1. **构建 AGH**（Node ≥24.10、pnpm 10.34.5、VS C++ Build Tools + Windows SDK）：`pnpm install --frozen-lockfile` → `prepare-windows-native.ps1` → `pnpm --filter @agnes/cli build:local`
2. **启动实验实例**：`AGH_HOME` 设为短路径（如 `D:\agh-home`）、`AGNES_PROFILE=local-dev`，再 `node packages/cli/dist/local/agnes.mjs serve`（默认 http://127.0.0.1:4177）
3. **配置模型**：Provider 选 **Agnes AI** → 测试连接 → 选模型 → 保存
4. **装 Skill**：把 `skills/formula-discovery-loop/` 放入 AGH skills 目录，按 `skills refresh` / `trust` 启用
5. **让智能体调用验证引擎**：要求它用命令工具执行 `harness\run_verify.cmd tasks\mech-gravity "G*m1*m2/r**2" G`，并读取 JSON 结论作为下一轮假设依据
6. **留证**：每次关键运行后 `agnes export <SESSION_ID> --html -o evidence/session.html` 与 `--format agnes -o .jsonl`

四个可直接用于答辩的论据：

1. 判据不是自说自话：每个任务的正确答案都能通过，每个物理上合理但结构错误的答案都被拒绝。
2. 我们知道自己方法的边界：参数出现在分母平方项时线性空间拟合必然失败，必须换对数空间多起点搜索，这个坑我们踩过并记录在案。
3. 失败也被记录，**而且我们推翻过自己的判据**：改造前的 `RMSE/std(y)` 会误杀正确的普朗克关系式，
   换成另一个同样合理的口径又会让结论随随机种子翻转。现在用的中位相对误差把金标准与错误式的间隔拉到 10.6 倍。
4. 小角度近似被拒这件事，我们改引 `scale-monotonic-theta0`（周期对振幅完全平坦）而不是任何一个误差数字——
   尺度判据不依赖阈值，换口径不会翻。旧文档里的 0.123 是历史口径 `RMSE/std(y)` 的数值，已作废。

## 七点六、自主闭环演示（无需模型账号）

    python examples/demo_agent.py --task phys-gravitation --run-id demo-gravitation
    python examples/demo_agent.py --task phys-pendulum-exact --run-id demo-self-negation

脚本用内置假设生成器模拟智能体的提议-否决-修正循环，全程调用真实验证引擎，
每轮写入 `runs/<run_id>/trajectory.jsonl`。加 `--llm` 并指定 `--agh-entry` 可改为调用 Agnes 模型生成假设。

> ⚠️ **默认模式下"假设"是人手写在脚本 `STRATEGIES` 表里的，不是模型提出的。**
> 因此这类运行的 `run.json.hypothesis_source` 标为 `human-authored-fixture`，
> **不得用于支撑"智能体自主发现"的结论**。它调用的是真实验证引擎，可以证明引擎的判别力，
> 不能证明智能体的能力。`--llm` 模式才标 `agh-llm`。

实测结果（2026-10-07 用统一阈值重跑，轨迹各 4 轮、不再重复）：

* 引力任务：4 轮、自我否决 3 次，最终恢复平方反比律，G = 6.66187e-11（真值 6.674e-11）。
* 单摆任务：第 1 轮小角度近似被同时被 `holdout` 与 **`scale-monotonic-theta0`** 否决；
  第 3、4 轮两个假设均通过且几乎不可区分，引擎如实报告多个假设通过，并用外推区误差裁决
  ——**不可区分的假设必须靠外推行为分辨**。
* 引用这一条时请用 `scale-monotonic-theta0`（周期对振幅完全平坦），它**不依赖任何误差阈值**；
  旧的"留出误差 0.1228"是已作废口径的数值，见第七点五节第 4 条。

## 八、已知边界（写进说明书，不藏）

* 像 `k*T` 这种「域内就差」的错误形式会在留出集阶段被拒，不会走到外推；这是正确的行为。
* 自由参数在量纲检验中视为无量纲，因此 `G*m1*m2/r**2` 会被标注「严格比对推迟」，而不是判为量纲一致——有意的取舍，已写入代码注释。
* 外推区依赖主自变量两端分位点；若真实任务两端数据极稀疏，需 M3 人工确认外推区是否合理。
* **符号错误判据识别不了**：自由参数会吸收符号（去掉引力势能的负号后，拟合出的 G 取负值即可完全等价）。
  这类错误交 M3 的物理审查兜底，已作为「无法识别」如实写进对抗性用例。
* **量纲检验在缺单位信息时降级**：降级结果仍是 `passed=True`，但理由写明「跳过」，契约校验同时给 warn。降级不会静默，但确实是降级。
* **封印只防目录遍历**：智能体若持有宿主机绝对路径仍可读到 `sealed/`，这依赖 AGH 的工作目录与沙箱策略。
* `runs/` 下由其它判定套件产出的运行（例如只跑尺度检验的 `scale-ref-*`），`recheck` 标为 `out-of-scope`，不做一致性断言。
* 工作区是三名成员共享的，`runs/` 会被并发写入；`archive` 检测到源文件变化时会重拷贝并在 `source_changed` 里列出，不静默覆盖。
